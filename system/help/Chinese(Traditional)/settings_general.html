程式設定

隨 Windows 一同啟動
在作業系統啟動時啟用 Open Server Panel 的自動啟動。
延遲
程式啟動延遲（秒，0 到 60）。

允許在隨 Windows 開機時延後啟動應用程式，以減少系統整體負載。若需要等待第三方服務或網路介面的完全初始化時，特別有用。
檢查是否有新版本
啟用檢查 Open Server Panel 更新（需要連線至網際網路）。
啟用排程器
啟用內建的排程器。若停用此參數，無論任務狀態如何，所有已排程的任務都不會執行。
使用 HOSTS 檔案
啟用將網域名稱寫入 HOSTS 檔案。

在組織中對 HOSTS 檔案存取受限時的建議：

1. 設定所有必要的模組與專案。
2. 聯繫系統管理員解除對 HOSTS 的封鎖並固定其狀態。
3. 管理員完成變更固定後即可關閉此選項。

重要： 若不確定後果，請勿關閉此參數！
以專案設定檔啟動模組
以同時啟用與專案名稱相同的設定檔方式啟動模組。

在選擇「啟用專案模組」選單項時使用，以便自動啟用與目前專案同名的設定檔（若存在）。
不關閉隱藏專案的模組
在選擇「關閉所有模組」選單項時，不關閉隱藏專案的模組。此處的「隱藏」指的是已設定類別為「hidden」的專案。

預設情況下，「關閉所有模組」命令會停止所有模組的運作，包括隱藏的系統專案所使用的模組（例如 PHPMyAdmin）。該選項允許在關閉其他模組的同時，保留隱藏系統專案所需模組的運作。
介面語言
Open Server Panel 的使用者介面語言。

若本地化檔案缺失或包含錯誤，將使用英文。
API 網域
用於 API 與網頁介面的本機網域（開發中）

建議： 若使用 VPN 或 Proxy，請將此網域加入例外。
API IP 位址
用於 API 與網頁介面的 IPv4 位址（開發中）。

建議： 若使用 VPN 或 Proxy，請將此 IP 位址加入例外。
API 埠
用於 API 與網頁介面的埠（開發中）。若指定的埠已被其他應用程式使用，Open Server Panel 將無法啟動。
使用 Windows Terminal
啟用使用 Windows Terminal 取代標準命令介面。

需求： 系統中必須已安裝 Windows Terminal，且已加入環境變數 PATH。

將 Windows Terminal 作為 cmd.exe： 在新版 Windows 中，Windows Terminal 可取代 cmd.exe，並寫入環境變數 %COMSPEC%。若是如此，請保持此選項為啟用狀態。

Windows Terminal 的新執行個體： 若 Windows Terminal 會開啟新視窗而非分頁，請如此設定：設定→啟動→新執行個體行為→附加到最後使用的視窗。
精簡專案標題
啟用此選項後，終端機視窗標題將僅顯示專案名稱，而非詳細的環境描述。
在專案環境中包含系統環境
在終端機中使用系統（System）環境，即使未在專案設定中指定。系統環境允許使用安裝於系統中的程式（例如 git.exe 或 ssh.exe）。

僅在與系統軟體發生衝突時才停用此選項。
ANSI 支援
啟用用於在終端機中控制顏色的 ANSI 代碼支援。

「自動」模式（預設）：
- 修正僅適用於 Windows 10 版本 1903（含）以前。在較新版本的 Windows 中已內建 ANSI 代碼支援。
- 對於預設支援 ANSI 的終端機（例如 Windows Terminal），不套用此修正。
搜尋專案的目錄
Open Server Panel 將搜尋專案的目錄清單。用分號（;）分隔路徑。

排除： 將忽略 node_modules 與 vendor 子目錄。
深度
搜尋專案時目錄的最大巢狀深度。

若提高此數值，而指定目錄中包含大量子目錄，可能會減慢 Open Server Panel 的啟動速度。
日誌檔案最大大小
以 MB 為單位的日誌檔案最大大小。當超過指定值時，日誌檔將在下次啟動程式時重新建立。

設為 0 可在每次啟動程式時清空日誌。

設為 100 MB 可完全停用日誌清理。
