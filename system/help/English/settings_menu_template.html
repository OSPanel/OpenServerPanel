Creating custom menu items

  1. Add a new section with a unique identifier [ID]
  2. Arrange the sections in the desired order — this will define the order of items in the menu
  3. Save changes and restart Open Server Panel to apply the changes

Important information

When creating custom menu items, make sure that section identifiers are not duplicated. This may lead to conflicts in the menu operation.

Menu item settings

Sort order: Menu items are sorted in the same order as the corresponding sections in the template.

caption Menu item title. Supports language constants in the format {lang_xxx}.

Default: not set
category

Determines the location of the menu item in the hierarchy. Supports one level of nesting (for example, "My Bookmarks\Work").

Special categories:

  • projects, modules, addons - adds an item to the corresponding actions menu
  • projects\, modules\, addons\ - adds an item for a specific element

If the category is not specified, the item is created in the root menu.

Default: not set
command The command to execute when the menu item is activated. Items without a command are ignored.

Default: not set
enabled Enables/disables the display of the menu item.

Default: on | Values: on, off
hide Controls the visibility of the launched application's window. Does not affect child processes.

Default: off | Values: on, off
hr_after Adds a horizontal separator after the menu item.

Default: off | Values: on, off
hr_before Adds a horizontal separator before the menu item.

Default: off | Values: on, off
icon Icon from the Font Awesome Free set (Solid/Regular/Brands).

Default: not set
need_alias Displays the menu item only for a domain alias. Only one item with need_alias=on can exist in a menu template!
Applicable for categories: projects

Default: not set | Values: on, off
need_category

Limits the display of a menu item to modules/addons of a specific category.

Supported formats:

  • modules, addons
  • modules\, addons\
Default: not set
need_module_shell Displays the menu item depending on whether the parent module has a shell/cli.
Applicable for categories: modules, modules\

Default: not set | Values: on, off
need_state Displays the menu item depending on the state of the parent module.
Applicable for categories: modules, modules\

Default: not set | Values: on, off
need_start_cmd Displays the menu item if a start command is present in the project settings.
Applicable for categories: projects, projects\

Default: not set | Values: on, off
need_use_wt Displays the menu item depending on the Windows Terminal usage setting in Open Server Panel.

Default: not set | Values: on, off
work_directory Working directory for executing the command. May change during command execution.

Default: {root_dir}

Template variables

In the "command" and "work_directory" parameters, you can use the following template variables:

Common variables

Variable Description
{date_time} Current date/time (variable available only for the "command" parameter)
{root_dir} Open Server Panel root directory (full path)
{root_drive} Root directory drive
{root_path} Path to the Open Server Panel root directory
{web_panel_url} Web interface URL

Special variables (only for projects and projects\<domain_name>)

Variable Description
{base_dir} Project base directory
{host} Domain name (Punycode)
{host_decoded} Visible domain name (without Punycode)
{host_scheme} Project request scheme ("http" or "https", depends on the TLS parameter in the project settings)
{http_port} Project request port via HTTP
{https_port} Project request port via HTTPS
{menu_caption} Menu item title (only for the projects category with need_alias=ON)
{http_engine} HTTP engine
{node_engine} Node.js engine
{php_engine} PHP engine
{project_root} Project root directory
{base_url} Project URL
{web_root} Project public directory
{scheme_port} Project request port (":{http_port}" or ":{https_port}", depends on the TLS parameter in the project settings). If {http_port} or {https_port} has the standard value 80 or 443, then {scheme_port} will be empty.
{app_start_command} Project application start command (if configured)
{terminal_codepage} Console encoding

Special variables (only for addons and addons\<addon_name>)

Variable Description
{addon_name} Add-on name
{terminal_codepage} Console encoding

Special variables (only for modules and modules\<module_name>)

Variable Description
{ip} Module IP address
{log_level} Error logging level
{module_name} Module name
{port} Module port
{profile_name} Current module settings profile name
{query_log_level} Query logging level
{shell_command} Module shell/cli launch command (if configured)
{terminal_codepage} Console encoding
{time_zone} Time zone

Special command values

Command Description
command_open_logs_viewer Open the logs viewer window
command_open_idn_converter Open the IDN converter
command_open_options Open the program settings window

In addition to template variables, you can use any Windows environment variables, for example: %SYSTEMROOT%, %SYSTEMDRIVE%, %USERNAME%, %PATH%, etc.

Usage example

[bookmark_1]

caption  = Google
category = My Bookmarks\Search Engines
command  = cmd.exe /c "start "" "https://google.com""
hide     = on
icon     = bookmark

CMD.EXE options

  • /c: Execute the command and close the terminal.
  • /k: Execute the command and keep the terminal open.
