Paramètres du programme

Lancer avec Windows
Activer le démarrage automatique d’Open Server Panel au chargement du système d’exploitation.
Délai
Délai de démarrage du programme (en secondes, de 0 à 60).

Permet de différer le lancement de l’application lors du chargement avec Windows afin de réduire la charge globale sur le système. C’est particulièrement utile si vous devez attendre l’initialisation complète de services tiers ou d’interfaces réseau.
Vérifier la présence de nouvelles versions
Activer la vérification des mises à jour d’Open Server Panel (connexion Internet requise).
Activer le Planificateur de tâches
Activer le planificateur de tâches intégré. Si le paramètre est désactivé, aucune tâche planifiée ne sera exécutée, quel que soit son statut.
Utiliser le fichier HOSTS
Activer l’écriture des noms de domaine dans le fichier HOSTS.

Recommandations en cas d’accès limité au fichier HOSTS dans l’organisation :

1. Configurez tous les modules et projets nécessaires.
2. Contactez l’administrateur système pour déverrouiller HOSTS et fixer son état.
3. Après la fixation des modifications par l’administrateur, vous pouvez désactiver cette option.

Important : Ne désactivez pas ce paramètre si vous n’êtes pas sûr des conséquences !
Lancer les modules avec le profil du projet
Lancer les modules avec activation simultanée du profil correspondant au nom du projet.

Utilisé lors du choix du menu « Activer les modules du projet » pour activer automatiquement le profil portant le même nom que le projet actuel, s’il existe.
Ne pas arrêter les modules des projets masqués
Ne pas arrêter les modules des projets masqués lors du choix du menu « Désactiver tous les modules ». Par « masqués », on entend les projets pour lesquels la catégorie « hidden » est définie.

Par défaut, la commande « Désactiver tous les modules » arrête absolument tous les modules, y compris ceux utilisés par des projets de service masqués (par exemple, PHPMyAdmin). Cette option permet de conserver le fonctionnement des projets de service masqués sans désactiver les modules nécessaires, tandis que tous les autres modules seront arrêtés.
Langue de l’interface
Langue de l’interface utilisateur d’Open Server Panel.

Si le fichier de localisation est absent ou contient des erreurs, l’anglais sera utilisé.
Domaine de l’API
Domaine local pour l’API et l’interface web (en développement)

Recommandation : Si un VPN ou un proxy est utilisé, ajoutez ce domaine aux exceptions.
Adresse IP de l’API
Adresse IPv4 pour l’API et l’interface web (en développement).

Recommandation : Si un VPN ou un proxy est utilisé, ajoutez cette adresse IP aux exceptions.
Port de l’API
Port utilisé pour l’API et l’interface web (en développement). Open Server Panel ne pourra pas démarrer si le port indiqué est déjà utilisé par une autre application.
Utiliser Windows Terminal
Activer l’utilisation de Windows Terminal au lieu de l’interface de commande standard.

Exigences : Windows Terminal doit être installé sur le système et présent dans la variable d’environnement PATH.

Windows Terminal comme cmd.exe : Windows Terminal peut remplacer cmd.exe et être défini dans la variable d’environnement %COMSPEC% dans les nouvelles versions de Windows. Si c’est le cas, laissez cette option activée.

Nouveaux instances de Windows Terminal : Si Windows Terminal ouvre de nouvelles fenêtres au lieu d’onglets, configurez-le ainsi : Paramètres→Démarrage→Comportement d’une nouvelle instance→Joindre à la dernière fenêtre utilisée.
Titre court du projet
Lorsque cette option est activée, seul le nom du projet sera affiché dans le titre de la fenêtre du terminal au lieu de la description détaillée de l’environnement.
Inclure l’environnement système dans l’environnement du projet
Utiliser l’environnement du système (System) dans le terminal, même s’il n’est pas défini dans les paramètres du projet. L’environnement système permet d’utiliser les programmes installés sur le système (par exemple, git.exe ou ssh.exe).

Désactivez cette option uniquement en cas de conflits avec des logiciels système.
Prise en charge ANSI
Activer la prise en charge des codes ANSI pour la gestion des couleurs dans le terminal.

Mode « Automatique » (par défaut) :
- La correction s’applique uniquement à Windows 10 jusqu’à la version 1903 incluse. Dans les versions plus récentes de Windows, la prise en charge des codes ANSI est déjà intégrée.
- La correction ne s’applique pas aux terminaux prenant en charge ANSI par défaut (par exemple, Windows Terminal).
Répertoires pour la recherche de projets
Liste des répertoires dans lesquels Open Server Panel recherchera des projets. Séparez les chemins par un point-virgule (;).

Exceptions : Les sous-répertoires node_modules et vendor sont ignorés.
Profondeur
Profondeur maximale d’imbrication des répertoires lors de la recherche de projets.

L’augmentation de cette valeur peut ralentir le démarrage d’Open Server Panel si les répertoires spécifiés contiennent un grand nombre de sous-répertoires.
Taille maximale du fichier journal
Taille maximale du fichier journal en mégaoctets. En cas de dépassement de la valeur indiquée, le fichier journal sera recréé au prochain démarrage du programme.

Définissez la valeur 0 pour effacer les journaux à chaque démarrage du programme.

Définissez la valeur 100 Mo pour désactiver complètement l’effacement des journaux.
