प्रोग्राम की सेटिंग्स

Windows के साथ चालू करें
ऑपरेटिंग सिस्टम के लोड होने पर Open Server Panel का ऑटोस्टार्ट सक्षम करें।
विलंब
कार्यक्रम शुरू करने में विलंब (सेकंड में, 0 से 60 तक)।

Windows के साथ स्टार्टअप के दौरान ऐप्लिकेशन के शुरू होने को टालने की अनुमति देता है ताकि सिस्टम पर कुल लोड कम हो। यह विशेष रूप से उपयोगी है, यदि तृतीय-पक्ष सेवाओं या नेटवर्क इंटरफेस की पूर्ण initialization का इंतजार करना हो।
नई संस्करणों की उपलब्धता की जाँच करें
Open Server Panel के अपडेट की जाँच सक्षम करें (इंटरनेट कनेक्शन आवश्यक)।
जॉब शेड्यूलर सक्षम करें
बिल्ट-इन जॉब शेड्यूलर सक्रिय करें। यदि पैरामीटर बंद है, तो उनकी स्थिति की परवाह किए बिना कोई भी निर्धारित जॉब निष्पादित नहीं होगा।
HOSTS फ़ाइल का उपयोग करें
डोमेन नामों को HOSTS फ़ाइल में लिखना सक्षम करें।

संगठन में HOSTS फ़ाइल तक सीमित पहुंच होने पर सिफारिशें:

1. सभी आवश्यक मॉड्यूल और प्रोजेक्ट्स को सेटअप करें।
2. HOSTS को अनलॉक करने और उसकी स्थिति फिक्स करने के लिए सिस्टम ऐडमिनिस्ट्रेटर से संपर्क करें।
3. ऐडमिनिस्ट्रेटर द्वारा बदलाव फिक्स करने के बाद इस विकल्प को बंद किया जा सकता है।

महत्वपूर्ण: यदि परिणामों के बारे में सुनिश्चित नहीं हैं, तो इस पैरामीटर को बंद न करें!
प्रोजेक्ट प्रोफाइल के साथ मॉड्यूल चलाएँ
मॉड्यूल्स को उस प्रोफ़ाइल की एक साथ सक्रियता के साथ चलाएँ, जो प्रोजेक्ट के नाम से मेल खाती हो।

मेनू आइटम «प्रोजेक्ट के मॉड्यूल सक्षम करें» चुनने पर उपयोग किया जाता है, ताकि यदि मौजूद हो तो वर्तमान प्रोजेक्ट के समान नाम वाले प्रोफ़ाइल को स्वतः सक्रिय किया जा सके।
छिपे हुए प्रोजेक्ट्स के मॉड्यूल बंद न करें
मेनू आइटम «सभी मॉड्यूल बंद करें» चुनने पर छिपे हुए प्रोजेक्ट्स के मॉड्यूल बंद न करें। "छिपे हुए" से तात्पर्य उन प्रोजेक्ट्स से है, जिनके लिए "hidden" श्रेणी सेट की गई है।

डिफ़ॉल्ट रूप से «सभी मॉड्यूल बंद करें» कमांड सभी मॉड्यूल्स के काम को रोक देती है, उन मॉड्यूल्स सहित जो छिपे हुए सेवा प्रोजेक्ट्स (उदाहरण के लिए, PHPMyAdmin) द्वारा उपयोग किए जाते हैं। यह विकल्प छिपे हुए सेवा प्रोजेक्ट्स की कार्यक्षमता को बनाए रखने की अनुमति देता है, उनके लिए आवश्यक मॉड्यूल्स को बंद किए बिना, जबकि बाकी सभी मॉड्यूल्स बंद हो जाएंगे।
इंटरफेस भाषा
Open Server Panel का यूजर इंटरफेस भाषा।

यदि लोकलाइज़ेशन फ़ाइल अनुपस्थित है या उसमें त्रुटियाँ हैं, तो अंग्रेज़ी भाषा उपयोग की जाएगी।
API डोमेन
API और वेब-इंटरफेस के लिए स्थानीय डोमेन (विकासाधीन)

सिफारिश: यदि VPN या प्रॉक्सी का उपयोग होता है, तो इस डोमेन को अपवादों में जोड़ें।
API IP-पता
API और वेब-इंटरफेस के लिए IPv4-पता (विकासाधीन)।

सिफारिश: यदि VPN या प्रॉक्सी का उपयोग होता है, तो इस IP-पते को अपवादों में जोड़ें।
API पोर्ट
API और वेब-इंटरफेस के लिए उपयोग किया जाने वाला पोर्ट (विकासाधीन)। यदि निर्दिष्ट पोर्ट पहले से किसी अन्य एप्लिकेशन द्वारा उपयोग में है, तो Open Server Panel शुरू नहीं हो पाएगा।
Windows Terminal का उपयोग करें
मानक कमांड इंटरफेस के बजाय Windows Terminal का उपयोग सक्षम करें।

आवश्यकताएँ: Windows Terminal सिस्टम में स्थापित होना चाहिए और PATH पर्यावरण चर में दर्ज होना चाहिए।

cmd.exe के रूप में Windows Terminal: Windows Terminal स्वयं cmd.exe को बदल सकता है और Windows के नए संस्करणों में %COMSPEC% पर्यावरण चर में दर्ज हो सकता है। यदि ऐसा है, तो इस विकल्प को सक्षम ही रहने दें।

Windows Terminal के नए इंस्टेंस: यदि Windows Terminal टैब्स की बजाय नई विंडो खोलता है, तो इसे इस प्रकार कॉन्फ़िगर करें: सेटिंग्स→स्टार्टअप→नए इंस्टेंस का व्यवहार→अंतिम उपयोग की गई विंडो से जोड़ें।
प्रोजेक्ट का छोटा शीर्षक
इस विकल्प के सक्रिय होने पर टर्मिनल विंडो के शीर्षक में विस्तृत वातावरण विवरण के बजाय केवल प्रोजेक्ट का नाम प्रदर्शित होगा।
प्रोजेक्ट के वातावरण में सिस्टम Environment शामिल करें
टर्मिनल में सिस्टम (System) Environment का उपयोग करें, भले ही वह प्रोजेक्ट सेटिंग्स में निर्दिष्ट न हो। सिस्टम Environment सिस्टम में इंस्टॉल किए गए प्रोग्राम्स (उदाहरण के लिए, git.exe या ssh.exe) का उपयोग करने की अनुमति देता है।

इस विकल्प को केवल तब बंद करें जब सिस्टम सॉफ़्टवेयर के साथ संघर्ष उत्पन्न हों।
ANSI समर्थन
टर्मिनल में रंगों को नियंत्रित करने के लिए ANSI-कोड्स का समर्थन सक्षम करें।

"स्वचालित" मोड (डिफ़ॉल्ट):
- फिक्स केवल Windows 10 संस्करण 1903 तक (शामिल) लागू होता है। Windows के नए संस्करणों में ANSI-कोड्स का समर्थन पहले से अंतर्निहित है।
- फिक्स उन टर्मिनलों पर लागू नहीं होता जो डिफ़ॉल्ट रूप से ANSI का समर्थन करते हैं (उदाहरण के लिए, Windows Terminal)।
प्रोजेक्ट्स खोजने के लिए डायरेक्टरीज़
उन डायरेक्टरीज़ की सूची, जिनमें Open Server Panel प्रोजेक्ट्स खोजेगा। पाथ्स को सेमीकोलन (;) से अलग करें।

अपवाद: node_modules और vendor उप-डायरेक्टरीज़ को अनदेखा किया जाता है।
गहराई
प्रोजेक्ट्स की खोज करते समय डायरेक्टरी नेस्टिंग की अधिकतम गहराई।

यदि निर्दिष्ट डायरेक्टरीज़ में बड़ी संख्या में उप-डायरेक्टरीज़ हैं, तो इस मान को बढ़ाने से Open Server Panel का स्टार्टअप धीमा हो सकता है।
लॉग फ़ाइल का अधिकतम आकार
लॉग फ़ाइल का अधिकतम आकार मेगाबाइट्स में। निर्दिष्ट मान से अधिक होने पर लॉग-फ़ाइल प्रोग्राम के अगले स्टार्टअप पर पुनः बनाई जाएगी।

कार्यक्रम के प्रत्येक स्टार्टअप पर लॉग्स साफ़ करने के लिए मान 0 सेट करें।

लॉग्स की सफाई पूरी तरह बंद करने के लिए 100 MB का मान सेट करें।
