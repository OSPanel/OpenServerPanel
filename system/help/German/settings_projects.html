Globale Projekteinstellungen

Die Parameter, die in diesem Abschnitt festgelegt sind, werden verwendet, wenn in den Projekteinstellungen keine anderen Werte angegeben sind.

Nginx
Bestimmt die verwendete Version des Nginx-Webservers für Projekte.
Node
Gibt die Node.js-Engine zum Ausführen von Node.js-Anwendungen an.

Node.js Installation: Installieren Sie vorab die gewünschte Node.js-Version mit Hilfe der NVM-Erweiterung.
PHP
Bestimmt die verwendete PHP-Engine zur Verarbeitung von PHP-Dateien.

Wichtig: PHP-Module ohne FCGI-Präfix sind integrierte Apache+PHP-Module.
Aktivieren
Bestimmt den Standardstatus des Projekts (aktiviert oder deaktiviert).
Terminal-Codierung
Zeichencodierung des Terminals bei der Arbeit mit der Projektumgebung.

Spezielle Werte:
- system: Die Systemcodierung wird verwendet.

Wichtig: Wenn kein Wert festgelegt ist, wird bei der Erstellung der endgültigen Projektumgebung die Terminal-Codierung durch die zuletzt verbundene Umgebung festgelegt, in der sie definiert ist, zum Beispiel durch die Umgebung des PHP-Moduls.
IP
Legt die IP-Adresse(n) fest, die von allen Projekten ohne individuelle Einstellungen verwendet werden.

Einschränkung: Projekte, die dieselbe IP-Adresse verwenden, müssen mit derselben PHP-Version arbeiten.

Unterstützung mehrerer IPs: Es können mehrere IP-Adressen durch Leerzeichen getrennt angegeben werden, einschließlich IPv6. In der HOSTS-Datei wird den Domains die erste angegebene IP zugewiesen.

Automatische Zuweisung: Wenn das Feld leer gelassen wird, wird die IP-Adresse automatisch zugewiesen.

Empfehlungen:
  • Die automatische Verwaltung von IP-Adressen wird für die meisten Benutzer empfohlen.
  • Die manuelle Festlegung einer IP-Adresse sollte nur bei spezifischen Netzwerkkonfigurationsanforderungen verwendet werden.
HTTP
Bestimmt den Port für HTTP-Verbindungen.
HTTPS
Bestimmt den Port für HTTPS-Verbindungen.
SSL
Aktiviert oder deaktiviert die SSL-Unterstützung für Projekte ohne individuelle Einstellungen.
Zertifikatsdatei
Gibt den Pfad zur SSL-Zertifikatsdatei an. Template-Variablen können verwendet werden.

Zulässige Zeichen: A-Za-z0-9-+_.\:

Empfehlung: Lassen Sie das Feld leer, um Zertifikate automatisch zu generieren.
Schlüsseldatei
Gibt den Pfad zur SSL-Schlüsseldatei an. Template-Variablen können verwendet werden.

Zulässige Zeichen: A-Za-z0-9-+_.\:

Empfehlung: Lassen Sie das Feld leer, um den Schlüssel automatisch zu generieren.
IP-Adresse (Backend)
Gibt die IP-Adresse an, über die die Verbindung zum Backend hergestellt wird.
Port (Backend)
Bestimmt die Portnummer für die Verbindung zum Backend.
Aktivieren (Backend)
Ermöglicht das automatische Weiterleiten des gesamten eingehenden Projektverkehrs (HTTP und HTTPS) an das Backend. Nützlich für Tests oder Entwicklung, wenn Frontend und Backend getrennt sind.
Projektverzeichnis
Gibt das Stammverzeichnis des Projekts an. Der Wechsel in dieses Verzeichnis erfolgt mit dem Befehl osp project <DOMAIN> bei gleichzeitiger Aktivierung der Projektumgebung. Template-Variablen können verwendet werden.

Erlaubte Zeichen: A-Za-z0-9-+_.\:
Öffentliches Verzeichnis
Bestimmt das öffentliche Verzeichnis des Projekts. Template-Variablen können verwendet werden.

Erlaubte Zeichen: A-Za-z0-9-+_.\:
Aliase
Gibt zusätzliche Domainnamen (Aliase) für das Projekt an (durch Leerzeichen getrennt). Template-Variablen können verwendet werden.

Subdomains: Wenn ein Alias keinen Punkt enthält, wird er als Subdomain betrachtet (z.B. "www" -> "www.test.local").

Einschränkung: Das Zeichen "*" wird in der Windows-HOSTS-Datei nicht unterstützt und erfordert eine DNS-Konfiguration.
Projektumgebung
Liste der Erweiterungen und Module (durch Leerzeichen getrennt), die die Projektumgebung bilden.

PHP/Nginx/Node.js-Module: Die Umgebungen dieser Module werden immer verbunden (wenn sie für die Domain festgelegt sind) und müssen in diesem Parameter nicht angegeben werden.
Projektstartbefehl
Definiert den Befehl zum Starten des Projekts (z.B. nodemon app.js). Template-Variablen können verwendet werden.
Projekt-URL
URL, die beim Auswählen von Projekt im Browser öffnen im Open Server Panel geöffnet wird. Template-Variablen können verwendet werden.

Anwendung: Kann die URL des CMS-Administrationsbereichs festlegen.

Template-Variablen

Variable Beschreibung
{backend_ip} IP-Adresse für die Verbindung zum Backend
{backend_port} Port für die Verbindung zum Backend
{base_dir} Stammverzeichnis des Projekts (wo sich das .osp-Verzeichnis befindet)
{host} Domainname (für internationalisierte Domains wird Punycode verwendet)
{host_decoded} Sichtbarer Domainname (ohne Punycode)
{host_scheme} Schema der Projektanfrage ("http" oder "https", abhängig vom SSL-Parameter in den Projekteinstellungen)
{http_port} Port für Projektanfragen über das HTTP-Protokoll
{https_port} Port für Projektanfragen über das HTTPS-Protokoll
{nginx_engine} Nginx-Engine
{node_engine} Node.js-Engine
{php_engine} PHP-Engine
{project_dir} Stammverzeichnis des Projekts
{public_dir} Öffentliches Verzeichnis des Projekts
{scheme_port} Port für Projektanfragen (":{http_port}" oder ":{https_port}", abhängig vom SSL-Parameter in den Projekteinstellungen).

Wenn {http_port} oder {https_port} den Standardwert 80 oder 443 hat, wird {scheme_port} leer sein.
{root_dir} Stammverzeichnis des Open Server Panels (vollständiger Pfad)
{root_drive} Laufwerk des Stammverzeichnisses
{root_path} Pfad zum Stammverzeichnis des Open Server Panels
{terminal_codepage} Konsolencodierung
